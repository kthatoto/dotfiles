# Global Preferences

Claude Code / Codex 共通のグローバル指示。ツール固有の設定は各ツールの指示ファイル
（Claude Code: `~/.claude/CLAUDE.md` / Codex: このファイルの後ろに続く記述なし）に置く。

## Communication

- 言語: 日本語
- 回答は簡潔・直接的に。前置きや過剰な要約を挟まない
- git のコミットメッセージは conventional commits 形式

## Development Style

- シンプルな解を先に。過度な設計をしない
- 新しくコードを書く前に既存実装を調べる
- 自前実装より枯れたライブラリを優先する

## Git Workflow

### Commit Message Format

```
<type>: <description>

<optional body>
```

Types: feat, fix, refactor, docs, test, chore, perf, ci

### Pull Request

PR を作るときは:

1. 最新コミットだけでなくコミット履歴全体を確認する
2. `git diff <base-branch>...HEAD` で全変更を把握する
3. 包括的な PR サマリを書く
4. TODO 形式のテストプランを含める
5. 新規ブランチは `-u` 付きで push する

## Session Hygiene

- タスク境界でコンテキストをリセットする。前タスクの文脈を引きずったまま新タスクを始めない
- 大きな中間成果物（調査結果・長い計画・大量ログ）は会話に溜めず、ファイルに書き出して参照渡しする
  - 一時的なもの → 一時ディレクトリ / 引き継ぐ計画・調査 → リポジトリ内の md / 永続知識 → メモリ
- 長い会話はフェーズ境界で自分から圧縮する。自動圧縮任せにしない
- サブエージェントへ委譲したら生ログを本会話に貼り戻さない。要約だけ受け取る

## Knowledge Wiki (LLM Wiki Pattern)

会話を通じて得た知識を、メモリ上で構造化・相互リンクされた Wiki として蓄積する。

### 原則

- **Ingest**: 新しい知識を得たら、関連する既存ページも確認・更新する（孤立させない）
- **Cross-link**: メモリファイルの本文中で関連ファイルへのリンクを張る
- **Consolidate**: 同じトピックの断片的な知識は1ページに統合する。重複ファイルを作らない
- **Scope**: プロジェクト固有 → そのプロジェクトのメモリ、汎用知識 → ユーザーグローバルのメモリ

### やらないこと

- コードから読み取れること、git history で分かることは書かない
- 1会話限りの作業状態はメモリに入れない（タスクやプランを使う）
- 過度に細かいページ分割はしない。1トピック1ページ
